# Aegis v1.1.0

[English](#english) · [Русский](#русский)

## English

### File manager

- Calculate folder sizes from the Size column or grid view.
- Calculate all folder sizes on the current page; sorting uses the calculated values.
- Loading, error and retry states; results are keyed by full path.
- The server merges identical requests, caches results for 30 seconds and runs at most two scans concurrently. Permission errors are not reported as zero bytes.
- Directory metadata reads have bounded concurrency; incomplete uploads do not leave partial files.

### Security

- Fastify 5 and compatible plugins, with a consistent lockfile.
- Restricted initial setup tokens: the default password cannot grant server management access before it is replaced.
- Asynchronous password hashing, login attempt and concurrency limits, and a 12-character minimum for new passwords.
- Password changes, 2FA configuration and logout revoke the relevant sessions and WebSocket connections.
- Terminal ownership, event-size and PTY-dimension checks; token validity is checked on every terminal event.
- Dynamic system commands run as a program and arguments without a shell; identifiers and dangerous parameters are validated.
- An optional observer account through AEGIS_VIEWER_USER / AEGIS_VIEWER_PASSWORD cannot modify the system, open a terminal or read arbitrary files.
- Fresh installations generate a random password instead of public admin/admin credentials. Existing passwords and TOTP settings are preserved.

### Monitoring and performance

- Removed random metrics and demo entries. A disconnected dashboard shows the last received values and their timestamp.
- Shared caching and request coalescing for metrics, processes, services and notifications.
- Metric collections do not overlap. /proc reads are asynchronous, CPU calculations use CLK_TCK, and processes are sorted before the result limit is applied.
- CPU, RAM, disk and network history survives restarts; the chart switches between five metrics.
- Extraction no longer recursively scans a directory every 600 ms.
- Background job counts are bounded, completed jobs are cleaned up, and apt operations share a lock.
- Main polling loops pause in hidden tabs and avoid overlapping requests; API requests have deadlines.
- Monocraft uses WOFF2: approximately 447 KB instead of 5.9 MB, loaded when selected.

### Usability and maintenance

- A persistent Activity page records user, time, operation and HTTP status. Passwords, request bodies and terminal input are not recorded.
- Failed-service notifications open the relevant logs; disk warnings open the corresponding directory.
- Save multiple server profiles in settings. Each panel opens with its own session; centralized server management is not included.
- Authentication, commands, caching, storage and updating are separate modules.
- The installer checks Node >=22, uses pnpm 11.25.0 and frozen lockfiles, and installs tmux/zip/unzip.

### Updating

On an existing panel, open **Settings → Panel update → Check → Update**.

The agent entry point remains compatible with the older updater: after the new source is copied, agent dependencies are installed automatically from the lockfile. The first upgrade may take longer; sign in again after the restart. Existing passwords, TOTP and port settings are preserved.

Updates started from v1.1.0 are built separately, smoke-tested, switched by a separate systemd job and rolled back automatically if the health check fails. The first upgrade still uses the older updater and retains its limitations.

GitHub Actions publishes the release only after Linux tests, the build and legacy updater dependency migration checks pass. The running server is not updated automatically.

## Русский

### Файловый менеджер

- Размер папки рассчитывается прямо из колонки «Размер» и в режиме сетки.
- Кнопка расчёта размеров всех папок текущей страницы; сортировка учитывает рассчитанные значения.
- Показ ожидания, ошибки и повторного расчёта. Результаты привязаны к полному пути.
- Сервер объединяет одинаковые запросы, кэширует результат на 30 секунд и выполняет не более двух обходов одновременно. Ошибка доступа не выдаётся за размер 0.
- Ограничена параллельность чтения метаданных каталогов; незавершённая загрузка не оставляет частичный файл.

### Безопасность

- Fastify 5 и совместимые версии плагинов; актуальный согласованный lock-файл.
- Ограниченные токены первоначальной настройки: стандартный пароль не даёт доступ к управлению сервером до его замены.
- Асинхронное хэширование паролей, ограничение попыток и параллельных проверок входа, минимум 12 символов для нового пароля.
- Смена пароля, настройка 2FA и выход отзывают ранее выданные сессии и WebSocket-подключения.
- Проверка владельца терминала, размера событий и размеров PTY; сервер проверяет действительность токена при каждом событии терминала.
- Динамические системные команды выполняются как программа и аргументы без shell; добавлена проверка идентификаторов и опасных параметров.
- Отдельная учётная запись наблюдателя через AEGIS_VIEWER_USER / AEGIS_VIEWER_PASSWORD. Она не может изменять систему, открывать терминал или читать произвольные файлы.
- Новая установка генерирует случайный пароль вместо публичного admin/admin. Существующие пароль и TOTP сохраняются.

### Мониторинг и производительность

- Убраны случайные метрики и демонстрационные записи. При потере связи отображаются последние данные и время замера.
- Единый кэш и объединение одновременных запросов метрик, процессов, сервисов и уведомлений.
- Замеры метрик не перекрываются. Чтение /proc асинхронное, учитывается CLK_TCK, процессы сортируются перед ограничением списка.
- История CPU, RAM, диска и сетевого трафика сохраняется между перезапусками; график переключается между пятью показателями.
- При распаковке больше нет полного обхода каталога каждые 600 мс.
- Ограничено количество фоновых заданий; завершённые задания очищаются, операции apt защищены общей блокировкой.
- Приостанавливается фоновый опрос скрытой вкладки, добавлены таймауты API и защита от перекрытия основных опросов.
- Monocraft переведён в WOFF2: примерно 447 КБ вместо 5,9 МБ, загрузка по выбору шрифта.

### Удобство и сопровождение

- Раздел «Действия»: сохраняемый журнал изменений с пользователем, временем, операцией и HTTP-статусом. Пароли, тела запросов и ввод терминала не записываются.
- Уведомление о сбое сервиса открывает его журнал, предупреждение о диске — соответствующий каталог.
- В настройках можно сохранить профили нескольких серверов. Каждая панель открывается со своей отдельной сессией; агрегированного управления серверами в этом релизе нет.
- Авторизация, команды, кэширование, хранение данных и обновление вынесены в отдельные модули.
- Установщик проверяет Node >=22, использует pnpm 11.25.0 и frozen lock-файлы, устанавливает tmux/zip/unzip.

### Обновление

На уже установленной панели: **Настройки → Обновление панели → Проверить → Обновить**.

Входной файл агента сохраняет совместимость со старым обновлятором: после копирования новой версии автоматически устанавливаются зависимости агента по lock-файлу. Во время первого перехода возможна дополнительная пауза; после перезапуска потребуется войти заново. Существующие пароль, TOTP и порт сохраняются.

Обновления, запущенные уже из v1.1.0, собираются отдельно, проходят smoke-проверку, переключаются отдельным systemd-заданием и автоматически откатываются при неудачной проверке здоровья. Первый переход выполняется старым обновлятором и сохраняет его ограничения.

Релиз публикуется GitHub Actions только после Linux-тестов, сборки и проверки миграции старого обновлятора. Рабочий сервер автоматически не обновляется.
